# راهنمای استقرار امن (بدون ریست داده‌ها) و خروج از حالت دمو

## ۱) قول‌هایی که کد به شما می‌دهد
- **هیچ بخشی از برنامه در زمان اجرا داده‌ای را حذف یا بازنویسی نمی‌کند.** Seed دمو فقط جدول‌های **خالی** را پر می‌کند.
- مقدارهای موجود (قیمت اتاق، تنظیمات، سفارش‌ها، حساب‌ها، اسناد) هرگز با دیفالت‌ها جایگزین نمی‌شوند؛ backfill فقط فیلدهای **خالی** را پر می‌کند.
- تغییرات ساختاری دیتابیس با **مایگریشن نسخه‌دار** انجام می‌شود (`migrations/`)، نه با `drizzle-kit push --force`.
- اسکریپت پاک‌سازی دمو (`scripts/purge-demo.mjs`) فقط با تأیید صریح `--yes` و فقط روی رکوردهای دمو کار می‌کند و به ادمین/تنظیمات/اتاق‌ها/حساب‌ها دست نمی‌زند.

## ۲) قبل از هر دیپلوی (بکاپ)
```bash
pg_dump "$DATABASE_URL" > backup-$(date +%F-%H%M).sql
```

## ۳) روند دیپلوی
```bash
# ۱. کد جدید
git pull            # یا انتقال فایل‌ها
# ۲. وابستگی‌ها
rm -rf node_modules .next
npm install --include=dev --include=optional    # وابستگی‌های build و باینری‌های native مثل sharp
# ۳. مایگریشن (غیرمخرب)
node scripts/db-migrate.mjs
# ۳.۱. ایندکس‌های کارایی (idempotent و بدون تغییر داده)
node scripts/apply-indexes.mjs
# sharp باید روی همان سیستم‌عامل/معماری مقصد نصب شود؛ node_modules مک را به لینوکس کپی نکنید.
# ریپو فعلی lockfile ندارد؛ برای buildهای تکرارپذیر package-lock.json را تولید و همراه کد نگه دارید.
# محدودیت بدنه آپلود را در reverse proxy روی حدود ۶۱ MiB تنظیم کنید؛ formData پیش از بررسی اندازه فایل parse می‌شود.
# ۴. build و اجرا
npm run build
npm run start
# ۵. بررسی سلامت
curl -fsS https://your-domain.com/api/health
```

> **اولین استقرار روی دیتابیسی که قبلاً با `drizzle-kit push` ساخته شده:**
> ```bash
> node scripts/db-migrate.mjs --baseline   # فایل‌های فعلی را «اعمال‌شده» علامت می‌زند، بدون اجرای SQL
> ```
> از آن به بعد هر فایل SQL جدید در `migrations/` با `node scripts/db-migrate.mjs` اجرا می‌شود.
>
> **تغییر ساختاری جدید در آینده:**
> ```bash
> npx drizzle-kit generate     # تولید فایل SQL جدید بدون حذف داده
> node scripts/db-migrate.mjs  # اجرای همان فایل روی سرور
> ```
> برای حفظ داده‌ها، تغییرات را «افزایشی» نگه دارید (افزودن جدول/ستون با default). از حذف ستون یا تغییر نوع مخرب خودداری کنید.

## ۴) خروج از حالت دمو
در فایل محیطی سرور (`.env` یا Environment Variables):
```env
DEMO_MODE=false
# NEXT_PUBLIC_DEMO_CREDENTIALS را حذف یا false کنید
ADMIN_NAME=مدیر هتل
ADMIN_EMAIL=owner@example.com
ADMIN_PASSWORD=یک-رمز-قوی-حداقل-۸-کاراکتر
SESSION_COOKIE_SECURE=true     # فقط در صورت سرو روی HTTPS
NEXT_PUBLIC_SITE_URL=https://your-domain.com
APP_URL=https://your-domain.com     # دامنه HTTPS برای callback درگاه‌ها
# PAYMENT_CREDENTIALS_KEY را از `openssl rand -base64 32` بسازید و فقط در محیط امن سرور ثبت کنید.
```
سپس سرویس را ری‌استارت کنید. نتیجه:
- هیچ داده دمو جدیدی درج نمی‌شود (حتی اگر دیتابیس خالی باشد).
- اطلاعات ورود نمایشی در صفحه لاگین **نمایش داده نمی‌شود** (حتی با `DEMO_MODE=true`، فقط با `NEXT_PUBLIC_DEMO_CREDENTIALS=true` قابل نمایش است).
- اگر هیچ ادمینی وجود نداشته باشد و `ADMIN_EMAIL/ADMIN_PASSWORD` تنظیم شده باشند، همین یک حساب مدیر ساخته می‌شود. اگر حساب مدیر از قبل هست، مقادیر محیطی نادیده گرفته می‌شوند و **رمز فعلی تغییر نمی‌کند**.
- داده‌های فعلی (اتاق‌ها، تنظیمات، رزروها، حساب‌ها) دست‌نخورده می‌مانند.

### تغییر/بازیابی رمز مدیر بدون ریست داده
```bash
node scripts/set-admin-password.mjs --email owner@example.com --password 'NewStrongPass'
```

### به‌روزرسانی امن پس از هر تغییر کد
```bash
pg_dump "$DATABASE_URL" > backup-before-deploy.sql
npm install --include=dev --include=optional
node scripts/db-migrate.mjs
node scripts/apply-indexes.mjs
npm run build && npm run start
curl -fsS https://your-domain.com/api/health
```
اگر تغییر جدیدی در `migrations/` نباشد، این دستورات فقط وضعیت را بررسی می‌کنند و به داده‌ها کاری ندارند.

### حذف اختیاری محتوای دمو (یک‌بار)
پیشنهاد اول: حذف رکوردهای دمو از پنل مدیریت (رزروها، اتاق‌ها، پیام‌ها، گالری…).
یا اجرای اسکریپت محدود:
```bash
pg_dump "$DATABASE_URL" > backup-before-purge.sql
node scripts/purge-demo.mjs --yes
```
این اسکریپت فقط رزروهای دمو (`TRK-ATL%`)، پیام‌ها/نظرات دمو و اسناد/قیمت‌های نمونه را حذف می‌کند و به ادمین، تنظیمات، حساب‌ها، اتاق‌ها و گالری دست نمی‌زند.

## ۵) متغیرهای محیطی
| کلید | توضیح |
|---|---|
| `DATABASE_URL` | اتصال PostgreSQL (الزامی) |
| `DEMO_MODE` | `false` در تولید. فقط روی دیتابیس خالی اثر دارد. |
| `NEXT_PUBLIC_DEMO_CREDENTIALS` | فقط برای محیط دمو؛ نمایش اطلاعات ورود نمونه |
| `ADMIN_NAME` / `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ساخت اولین ادمین (فقط اگر هیچ ادمینی وجود نداشته باشد) |
| `SESSION_COOKIE_SECURE` | `true` فقط روی HTTPS |
| `NEXT_PUBLIC_SITE_URL` | آدرس عمومی برای RSS/لینک‌ها |
| `APP_URL` | دامنه عمومی HTTPS؛ مبدأ callback زرین‌پال، زیبال، سامان و ملت |
| `PAYMENT_CREDENTIALS_KEY` | کلید ۳۲ بایتی Base64 برای رمزگذاری AES-256-GCM اطلاعات پذیرنده در پایگاه داده؛ در بکاپ امن نگه دارید. |
| `ZARINPAL_MERCHANT_ID` | شناسه پذیرنده زرین‌پال (در صورت تنظیم، جایگزین مقدار پنل مدیریت) |
| `ZIBAL_MERCHANT` | شناسه پذیرنده زیبال (در صورت تنظیم، جایگزین مقدار پنل مدیریت) |
| `PG_POOL_MAX` | حداکثر اتصال استخر (پیش‌فرض ۵) |
| `SMS_PROVIDER` | `kavenegar` یا `smsir` |
| `ADMIN_SMS_PHONE` | گیرنده پیامک رزرو جدید |
| `KAVENEGAR_API_KEY` + `KAVENEGAR_PATTERN_*` | پترن‌های کاوه‌نگار |
| `SMSIR_API_KEY` + `SMSIR_TEMPLATE_*` | پترن‌های sms.ir |

## ۶) نکات سخت‌سازی تولید
- پیش‌فرض کد `DEMO_MODE=false` است؛ برای محتوای نمونه، فقط آگاهانه آن را `true` کنید.
- در تولید کوکی سشن به‌صورت پیش‌فرض `Secure` است؛ فقط پشت HTTPS اجرا کنید.
- پرداخت آنلاین زرین‌پال، زیبال، سامان و به‌پرداخت ملت از پنل «تنظیمات ← درگاه‌های پرداخت اینترنتی» فعال می‌شود. پیش از واردکردن اطلاعات پذیرنده، `PAYMENT_CREDENTIALS_KEY` را ثبت کنید؛ اطلاعات پذیرندهٔ ذخیره‌شده با AES-256-GCM رمز می‌شود و مقدار آن به مرورگر بازگردانده نمی‌شود. این کلید را در بکاپ امن نگه دارید؛ بدون آن رمزگشایی اطلاعات ممکن نیست. کلید و رمز پذیرنده را در مخزن کد قرار ندهید.
- پیش از فعال‌سازی درگاه، `APP_URL` را روی دامنه عمومی HTTPS تنظیم کنید و همان دامنه را نزد PSP ثبت کنید. هر تلاش پرداخت یک کلید تصادفی callback دارد؛ پاسخ callback به‌تنهایی پرداخت را قطعی نمی‌کند و سرور مبلغ را مستقیماً از درگاه استعلام می‌گیرد.
- بعد از اضافه شدن درگاه‌ها، روی دیتابیس موجود فقط `node scripts/db-migrate.mjs` را اجرا کنید تا مایگریشن افزایشی `0003_payment_gateways` اعمال شود؛ دستور `--baseline` را در این مرحله اجرا نکنید.
- کارت‌به‌کارت همچنان با بررسی رسید توسط پذیرش انجام می‌شود. شبیه‌ساز پرداخت فقط در حالت دمو فعال است.
- کلیدهای SMS فقط سمت سرور نگه داشته می‌شوند؛ در پنل `/admin/sms` وضعیت تنظیمات و لاگ‌ها را ببینید.
- برای محیط واقعی `DEMO_MODE=false` را صریح تنظیم کنید؛ بنر هشدار حالت دمو در داشبورد نمایش داده می‌شود.
- محدودکننده درخواست داخل برنامه حافظه‌ای و تک‌پردازه‌ای است؛ برای چند replica/serverless، محدودسازی توزیع‌شده در proxy یا Redis لازم است. proxy باید `CF-Connecting-IP` / `X-Real-IP` را بازنویسی کند، `X-Forwarded-For` ورودی کاربر را نپذیرد و دسترسی مستقیم به origin را ببندد.
- بکاپ روزانه + نگه‌داشتن `migrations/` در ریپو الزامی است.

## ۷) یک اسکریپت، چند هتل (۳ / ۴ / ۵ ستاره)
این نسخه برای چند نوع هتل قابل استفاده است و همه تفاوت‌ها از پنل مدیریت کنترل می‌شود:

- **درجه هتل**: `تنظیمات → هویت هتل` → «درجه هتل» (۳/۴/۵ ستاره). ستاره‌ها در هدر، فوتر، صفحه اصلی و درباره ما نمایش داده می‌شوند.
- **ماژول‌ها** (فعال/غیرفعال): استخر، رستوران، کافه، اسپا.
  - با غیرفعال کردن «استخر»، لینک منو، صفحه استخر، بخش صفحه اصلی و گزینه رزرو استخر مخفی می‌شود و API رزرو استخر درخواست را رد می‌کند.
  - با فعال بودن رستوران/کافه، صفحه «کافه و رستوران» و منوی آن فعال است.
- **کافه و رستوران**: در تنظیمات نام، معرفی، ساعت سرو، تلفن رزرو میز، تصاویر و ویدیو قابل ویرایش است؛ آیتم‌های منو در `/admin/menu` با دسته‌بندی/قیمت/تصویر مدیریت می‌شوند.
- **اتاق‌ها**: ظرفیت استاندارد/حداکثر، هزینه نفر اضافه، گزینه‌های پولی (صبحانه/ناهار/شام) و امکانات آیتمی مستقل از ستاره هتل کار می‌کنند.

### نمونه پیکربندی‌ها
| نوع هتل | ستاره | استخر | رستوران | کافه | اسپا |
|---|---|---|---|---|---|
| هتل کاج (نمونه این نسخه) | ۳ | خیر | بله | بله | خیر |
| هتل ۴ ستاره شهری | ۴ | بله | بله | بله | بله |
| هتل بوتیک بدون استخر | ۴ | خیر | بله | بله | خیر |

### تغییر برند نمونه (هتل کاج)
برای محیط دمو، اسکریپت `scripts/rebrand-kaj.mjs` برند/محتوای نمونه را روی دیتابیس موجود اعمال می‌کند. این اسکریپت **غیرمخرب و idempotent** است:
```bash
pg_dump "$DATABASE_URL" > backup-before-rebrand.sql
node scripts/rebrand-kaj.mjs --yes
```
- تنظیمات، امکانات، جاذبه‌ها، گالری، نظرات و منو را به‌روزرسانی می‌کند.
- رکوردهای قبلی را **غیرفعال** می‌کند (حذف نمی‌کند) و اتاق‌ها/رزروها/حساب‌ها/اسناد را دست نمی‌زند.
- داده‌های واقعی هتل شما بعد از راه‌اندازی، فقط از پنل مدیریت تغییر می‌کند.

### مایگریشن این نسخه
نسخه قبلی روی دیتابیس موجود:
```bash
node scripts/db-migrate.mjs --baseline   # فقط 0000 را «اعمال‌شده» علامت می‌زند
node scripts/db-migrate.mjs              # 0001 (ستاره/ماژول‌ها/دینینگ/منو) را اجرا می‌کند
node scripts/apply-indexes.mjs
```
دیتابیس تازه: فقط `node scripts/db-migrate.mjs` (هر دو مایگریشن اجرا می‌شود).

## ۸) نسخه چهارستاره (رابط کاربری پریمیوم)
این نسخه با یک طراحی جدید «شب‌آبی نفتی + شامپاین + عاجی» ارائه شده که مناسب هتل ۴ ستاره است:

- هدر شیشه‌ای تیره با نوار کانسیرژ، ستاره‌ها، منوی ماژول‌محور و CTA طلایی.
- هیروی سینمایی تمام‌عرض (تصویر/ویدیو/گیف) + نوار رزرو شیشه‌ای شناور.
- بخش تجربه‌ها (کافه‑رستوران، اسپا و سلامتی، باغ/تراس)، اتاق‌ها با کارت‌های اورلی، امکانات شبکه‌ای، جاذبه‌ها، نظرات و CTA نهایی با قاب طلایی.
- کارت اتاق، انتخاب تاریخ، منو و صفحات عمومی همگی با همان زبان طراحی پریمیوم به‌روز شده‌اند.

### ارتقای داده‌های نمونه به چهارستاره
```bash
pg_dump "$DATABASE_URL" > backup-before-4star.sql
node scripts/upgrade-four-star.mjs --yes
```
- `starRating=4`، ماژول اسپا فعال، استخر غیرفعال (قابل تغییر از پنل).
- افزودن امکانات «اسپا و سلامتی»، «تراس روفت»، «سالن جلسات» و تصاویر/نظرات جدید.
- کاملاً idempotent و غیرمخرب؛ اتاق‌ها، رزروها، حساب‌ها و اسناد دست‌نخورده می‌مانند.

برای هتل ۵ ستاره: همان مسیر با `starRating=5` و فعال‌کردن همه ماژول‌ها؛ برای هتل ۳ ستاره: `starRating=3` و غیرفعال‌کردن اسپا/استخر.

## ۹) نسخه رابط کاربری نئومورفیسم (Soft UI)
آخرین بازطراحی فرانت‌اند با زبان طراحی **نئومورفیک** انجام شده است:

- پس‌زمینه سنگی یکدست و سطوح «برجسته/فرورفته» با سایه‌های دوتایی (روشن/تیره) به‌جای خط و کادر.
- دکمه‌ها، ورودی‌ها، تب‌ها، نشان‌ها، تصاویر و کارت‌ها همگی با کلاس‌های `neu-raised`، `neu-inset`، `neu-pill`، `neu-circle`، `neu-img` و `neu-hover`.
- پالت آرام: سنگ گرم + سبز-آبی مریم‌گلی + رُسی؛ بدون بلوک‌های تیره.
- هدر شیشه‌ای روشن با منوی فرورفته و CTA برجسته؛ فوتر به‌صورت کارت برجسته.
- هیروی صفحه اصلی کارت برجسته با تصویر داخل قاب فرورفته، نوار رزرو درون‌فرورفته و آمار به‌صورت کاشی‌های نرم.
- صفحات اتاق، رزرو، کافه‑رستوران، تماس و گالری همگی با همین زبان طراحی هماهنگ شدند.

کلاس‌های `neu-*` در `src/app/globals.css` تعریف شده‌اند؛ برای تغییر شدت نرمی، مقادیر سایه‌ها و رنگ‌های `--color-neu-*` را ویرایش کنید. انتخاب تم سایت با `data-theme="soft"` در `src/app/layout.tsx` انجام می‌شود.

## ۱۰) نسخه رابط کاربری گلس‌مورفیسم (Glassmorphism)
آخرین بازطراحی فرانت‌اند روی سبک **شیشه‌ای (Glass)** انجام شده است:

- پس‌زمینه mesh-gradient با هاله‌های سبز، طلایی، آبی و مرجانی (ثابت هنگام اسکرول) و سطوح شیشه‌ای نیمه‌شفاف با `backdrop-blur`.
- کلاس‌های اختصاصی: `glass`، `glass-strong`، `glass-soft`، `glass-dark`، `glass-pill`، `glass-img`، `glass-circle`، `glass-hover`، `glass-divider`، `glass-sheen`.
- ناوبری شناور شیشه‌ای، فوتر کارتی، هیروی تیره شیشه‌ای با نوار رزرو شیشه‌ای روشن، کارت‌های شیشه‌ای در همه صفحات عمومی و فرم‌ها.
- **چیدمان جدید صفحه اصلی**: هیروی سینمایی + ریل آماری شیشه‌ای، موزاییک بنتو (تصویر/معرفی/آمار/نقل‌قول)، اتاق‌ها به‌صورت اسکرول افقی، تجربه‌ها به‌صورت ردیف‌های متناوب، اسپات‌لایت منوی کافه، امکانات شبکه‌ای، جاذبه‌ها به‌صورت لیست شماره‌دار، اسکرول نظرات، نقشه + پیگیری و موزاییک گالری + CTA شیشه‌ای تیره.
- تغییر شدت شیشه‌ای بودن با ویرایش `backdrop-filter`/`box-shadow` در کلاس‌های `glass-*` و تغییر رنگ‌ها با `--color-*` در `src/app/globals.css`.
- تم فعال: `data-theme="glass"` در `src/app/layout.tsx`.

> پنل مدیریت از همان داده‌ها و فرم‌ها استفاده می‌کند و صرفاً پوسته آن با پالت جدید رندر می‌شود؛ هیچ داده‌ای با تغییر تم ریست نمی‌شود.

## ۱۱) نسخه «آتلیه زمرد» + امکانات جدید مهمان
بازطراحی نهایی سایت با زبان طراحی **آتلیه زمرد** (Emerald Atelier) انجام شده است: هیروی سینمایی زمردی با قاب طلایی، بخشهای ادیتوریال، کارتهای شیشهای روی پسزمینه عاجی، تایپوگرافی بزرگتر، خطوط طلایی و بخشهای تیره/روشن متناوب.

### امکانات جدید (با ذخیرهسازی پایدار)
1. **پیشنهادها و پکیجها** (`offers`): بستههای اقامت + شام/اسپا/تور با قیمت، قیمت قبلی، مزایا و اعتبار. صفحه عمومی `/offers` و مدیریت در `/admin/offers`.
2. **رویدادها و تقویم تجربهها** (`events`): موسیقی زنده، شام سرآشپز، تور و کارگاه با تاریخ شمسی. صفحه `/events` و مدیریت `/admin/events`.
3. **کدهای تخفیف** (`promo_codes`): درصدی یا مبلغی، حداقل شب، سقف استفاده و تاریخ انقضا. اعتبارسنجی در `/api/promo/validate` و اعمال خودکار روی مبلغ رزرو؛ مصرف هر کد شمارش میشود. مدیریت در `/admin/promos`.
4. **نظرات مهمانان** (`reviews`): فرم ثبت نظر در `/reviews` (بدون نیاز به حساب)، انتشار پس از تأیید پذیرش، امتیازدهی و توزیع ستارهها. مدیریت/تأیید در `/admin/reviews`.
5. **خبرنامه** (`subscribers`): فرم عضویت درفوتر و صفحه اصلی؛ فهرست و مدیریت در `/admin/subscribers`.
6. **کانسیرژ و درخواست خدمات** (`concierge_requests`): ترانسفر، تور، اسپا، رزرو میز و مناسبتها. صفحه `/concierge` و مدیریت در `/admin/concierge`.
7. **اعمال کد تخفیف در فرم رزرو**: ورودی کد در خلاصه رزرو، نمایش تخفیف و مبلغ نهایی، ثبت در فیلدهای `promo_code` و `discount_amount` رزرو. بدون کد معتبر، رزرو ثبت نمیشود.
8. **داشبورد مدیریت**: کارتهای جدید برای نظرات در انتظار، درخواستهای کانسیرژ و مشترکان خبرنامه + بج در منو.

### مایگریشن این نسخه
```bash
node scripts/db-migrate.mjs --baseline   # برای دیتابیس‌های قبلی: 0000/0001/0002 فعلی را «اعمال‌شده» علامت می‌زند
node scripts/db-migrate.mjs              # از این پس مایگریشن‌های جدید را اجرا می‌کند
node scripts/apply-indexes.mjs
```
برای دیتابیس تازه فقط `node scripts/db-migrate.mjs` کافی است. در حالت دمو، محتوای نمونه پکیجها/رویدادها/کدها/نظرات فقط یک‌بار و در صورت خالی بودن جداول اضافه می‌شود؛ هیچ داده‌ای حذف یا بازنویسی نمی‌شود.

## ۱۲) موبایل، موتور تصویر و اعتبار طراحی
### ریسپانسیو
- تمام صفحات عمومی و پنل برای موبایل بازبینی و اصلاح شدند: منوهای کشویی، گریدهای تک‌ستونه، جدول‌های اسکرول‌شو، دکمه‌های بزرگ‌تر لمسی، نوار پایین موبایل (تماس/واتس‌اپ/رزرو)، فاصله امن پایین صفحه، و اسکرول افقی کارت‌ها با snap.
- در CSS: مدیا کوئری `max-width: 640px` برای تایپوگرافی، دکمه‌ها، ورودی‌ها و حذف تزئینات سنگین؛ `overflow-x: hidden` روی body برای جلوگیری از اسکرول افقی ناخواسته.
- لینک‌های تلفن با `phoneHref()` ساخته می‌شوند تا ارقام فارسی به شماره قابل تماس (+98) تبدیل شوند.

### موتور تصویر (WebP + دو نسخه + HEIC)
مسیر آپلود: `src/app/api/admin/upload/route.ts`
1. فرمت‌های ورودی: JPG، PNG، WebP، GIF، AVIF و **HEIC/HEIF** (تبدیل با `heic-convert`/libheif؛ در صورت پشتیبانی sharp نیز تلاش می‌شود).
2. همه تصاویر به **WebP** تبدیل می‌شوند و دو فایل ذخیره می‌شود:
   - `<name>-full.webp` — حداکثر ۱۹۲۰px، کیفیت ۸۲ (نسخه اصلی بهینه)
   - `<name>-thumb.webp` — حداکثر ۴۸۰px، کیفیت ۵۵ (نسخه کم‌حجم)
3. محدودیت حجم: تصویر ۲۵MB و ویدیو ۶۰MB؛ فایل‌های موقت پس از پردازش پاک می‌شوند.
4. ویدیوها (mp4/webm/mov) بدون تبدیل و به‌صورت استریم ذخیره می‌شوند.
5. در سایت، کامپوننت `SmartImage` ابتدا `-thumb.webp` را نمایش می‌دهد و پس از decode شدن نسخه `-full.webp` آن را جایگزین می‌کند (blur-up + fade). برای تصاویر خارجی (Pexels) نسخه کم‌حجم با پارامتر `w=560&q=45` ساخته می‌شود.
6. پاسخ API: `{ url, thumbUrl, width, height, size, thumbSize, sourceType }` — مقدار `url` را در فرم‌ها ذخیره کنید؛ نسخه thumb به‌صورت خودکار مشتق می‌شود.

> **مهم برای تولید:** پوشه `public/uploads` باید روی ولوم پایدار (Persistent Volume) باشد و در بکاپ‌ها گنجانده شود؛ در غیر این صورت با هر دیپلوی، رسانه‌های آپلودشده از دست می‌روند (دیتابیس دست‌نخورده است اما فایل‌ها باید پایدار بمانند).

### فوتر
- لینک «ورود مدیران» از فوتر حذف شد (پنل از مسیر `/admin/login` در دسترس است).
- متن پایین فوتر: «© ۱۴۰۴ تمامی حقوق برای {نام هتل} محفوظ است. · طراحی توسط آسرودیزاین» با لینک به `https://asrodev.ir` (نام هتل از تنظیمات خوانده می‌شود).

## ۱۳) بهینه‌سازی سرعت و بازطراحی صفحه اصلی
### نتایج اندازه‌گیری (قبل → بعد)
| شاخص | قبل | بعد |
|---|---|---|
| TTFB گرم صفحه اصلی | ~۱۰۰–۱۵۰ms | **~۷۰–۸۰ms** |
| حجم HTML (gzip) | ~۱۶۰KB | **~۳۳KB** |
| تصاویر صفحه اصلی | ۲۵ تصویر یکتا + ۴۱ ارجاع | **۶ تصویر تدریجی** |
| ویدیوی هیرو | دانلود خودکار ویدیو | **۰ در بارگذاری اولیه (پخش با کلیک)** |
| نقشه | iframe و تایل‌های OSM در لود اول | **بارگذاری فقط با کلیک** |

### چه چیزهایی بهینه شد
1. **تصاویر**
   - `SmartImage` حالا نسخه thumb را فوراً نشان می‌دهد و نسخه full را فقط وقتی تصویر به viewport نزدیک شد (IntersectionObserver + `requestIdleCallback`) دانلود می‌کند.
   - روی شبکه‌های کم‌سرعت/مصرف محدود (Save-Data، 2G) نسخه full دانلود نمی‌شود.
   - ابعاد تصاویر خارجی (Pexels) در لحظه رندر به حداکثر ۹۰۰px (و هیرو ۱۳۰۰px) با کیفیت ۷۰ محدود می‌شود؛ thumbnailها با `w=480&q=40`.
   - preconnect به CDN تصاویر و `fetchPriority`/`loading` صحیح؛ فقط هیرو eager است.
2. **ویدیو و نقشه**
   - ویدیوی معرفی هتل به‌صورت **اختیاری با دکمه پخش** بارگذاری می‌شود (دیگر در مسیر بارگذاری اولیه نیست).
   - نقشه OpenStreetMap تا کلیک کاربر mount نمی‌شود (کاهش درخواست‌های third-party).
3. **داده‌ها**
   - کش ۳۰ ثانیه‌ای با تگ برای محتوای عمومی (`unstable_cache`) + بی‌اعتبارسازی خودکار پس از هر تغییر در پنل (`revalidateTag`).
   - تنظیمات هتل (برند/هیرو) بدون کش خوانده می‌شود تا تغییرات پنل فوراً دیده شود.
   - `getReviewSummary` با یک کوئری تجمیعی جای خواندن ۵۰۰ نظر؛ صفحه اصلی تنها یک‌بار اتاق‌ها را می‌خواند و از testimonials جداگانه صرف‌نظر کرده است.
4. **رندر**
   - کاهش `backdrop-filter` روی کنترل‌های کوچک (فقط سطوح بزرگ blur دارند) و کاهش شدت blur در موبایل.
   - حذف `background-attachment: fixed`، کوچک‌تر شدن هاله‌های تزئینی و حذف آن‌ها در موبایل.
   - `content-visibility` برای بخش‌های پایین صفحه، حذف بخش‌های تکراری/سنگین از صفحه اصلی.

### صفحه اصلی جدید (کاربرپسندتر)
- هیروی دو ستونه با یک تصویر شاخص، نشان ستاره/شهر، CTA واضح «رزرو سوئیت» و لینک‌های سریع.
- نوار رزرو (تاریخ/مهمان) بلافاصله زیر هیرو، نوار اعتماد چهارگانه، اتاق‌های آماده رزرو با قیمت شفاف.
- پکیج‌ها با کدهای تخفیف، تجربه‌های کافه/اسپا، نظرات + رویدادها در یک ردیف، نقشه تنبل و CTA پایانی.
- نوار اکشن پایین موبایل (تماس/واتس‌اپ/رزرو) و حفظ دسترسی سریع به همه صفحات از هدر.

## ۱۴) پاس دوم بهینه‌سازی سرعت + صفحه اصلی جدید (نسخه ۴ ستاره)
### نتایج اندازه‌گیری (وضعیت نهایی)
| شاخص | نتیجه |
|---|---|
| TTFB گرم صفحه اصلی | **~۴۸–۵۷ms** |
| HTML صفحه اصلی (gzip) | **~۳۴KB** |
| CSS (gzip) | **~۲۹KB** |
| فونت | **۴۶KB عربی subset (preload) + ۳۴KB لاتین (فقط در صورت نیاز)** به‌جای ۱۱۱KB فونت کامل |
| تصاویر اولیه | **۷ تصویر تدریجی؛ فقط هیرو eager** |
| ویدیو/نقشه در لود اول | **۰ ویدیو، ۰ iframe** |

### بهینه‌سازی‌های این پاس
1. **فونت subset**: فونت Vazirmatn به دو subset (Arabic برای فارسی، Latin برای کدها/ایمیل) تقسیم شد و با `unicode-range` و `font-display: swap` سرو می‌شود؛ preload فقط برای subset عربی. حذف `next/font/local` و فایل ۱۱۱KB.
2. **انتخاب هوشمند ابعاد تصویر**: `SmartImage` بر اساس عرض viewport و DPR یک کاندید مناسب (موبایل ۶۲۰/هیرو ۷۲۰، تبلت ۸۰۰/۱۰۰۰، دسکتاپ تا ۱۱۰۰/۱۴۰۰) از CDN می‌گیرد؛ دیگر موبایل تصویر دسکتاپ را دانلود نمی‌کند و دانلود تکراری هم رخ نمی‌دهد.
3. **کاهش CSS و افکت‌های سنگین**: حذف کلاس‌های بی‌استفاده (`hero-mask`, `pattern-grid`, `lux-frame`, `tile-dark`, `marquee`, …)، حذف blur از کنترل‌های کوچک، محدودکردن backdrop به سطوح بزرگ، حذف هاله‌های blur در موبایل، حذف `background-attachment: fixed`.
4. **حذف hydration غیرضروری**: صفحه اصلی دیگر از کامپوننت Reveal (IntersectionObserver per section) استفاده نمی‌کند و بخش‌های پایین صفحه `content-visibility` دارند.
5. **کش لبه/پروکسی**: برای صفحات محتوایی (`/`, `/rooms`, `/offers`, `/events`, `/reviews`, `/facilities`, `/attractions`, `/gallery`, `/about`, `/contact`, `/dining`, `/pool`, صفحه اتاق) هدر `Cache-Control: public, s-maxage=60, stale-while-revalidate=300` تنظیم شد. اگر CDN/Nginx جلوی سایت باشد، صفحه از کش لبه با تأخیر نزدیک صفر سرو می‌شود. تغییرات پنل با تگ‌ریولیدیشن داده (۳۰ ثانیه) و حداکثر تا همین بازه در کش لبه تازه می‌شود.
6. **بدون بلاک‌کننده در مسیر اولیه**: ویدیو فقط با دکمه پخش، نقشه فقط با کلیک، تصاویر پایین صفحه فقط نزدیک viewport، فونت preload شده و اسکریپت‌ها deferred توسط Next.

### صفحه اصلی (بازطراحی نهایی)
- هیروی تمام‌عرض زمردی با تصویر شاخص (LCP بهینه)، عنوان بزرگ، امتیاز و قیمت شفاف، دکمه‌های «رزرو اقامت» و «پیشنهادهای ویژه».
- نوار رزرو (تاریخ/مهمان) درون هیرو، **ناوبری پرشی** به بخش‌ها (اتاق‌ها، پیشنهادها، کافه/اسپا، نظرات، موقعیت) و نوار اعتماد چهارگانه.
- اتاق‌های اسکرول‌شو با قیمت و ظرفیت، پکیج‌های ویژه با کد تخفیف، تجربه کافه/اسپا/کانسیرژ، امتیاز و نظرات + رویدادها، نقشه تنبل و CTA پایانی.
- لمسی/کاربرپسند: دکمه‌های بزرگ، لینک‌های واضح، نوار اکشن پایین موبایل، بدون پاپ‌آپ و بدون اسکرول افقی ناخواسته.
